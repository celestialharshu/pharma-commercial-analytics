# Power BI / Tableau Dashboard Guide

This guide describes how to build the 5-module dashboard on top of the
processed CSVs in `data/processed/` (or the PostgreSQL tables from
`sql/01_schema.sql` if you've loaded the data into a database).

## 1. Data sources to connect

| Table | Source | Role |
|---|---|---|
| `product_master.csv` | dim | Product dimension |
| `hcp_master.csv` | dim | HCP dimension |
| `sales_transactions.csv` | fact | Sales grain: date × product × HCP |
| `prescriptions.csv` | fact | Rx grain: date × product × HCP |
| `market_data.csv` | fact | Market grain: month × product |
| `patient_access.csv` | fact | Access grain: month × region × payer |
| `hcp_engagement.csv` | fact | Engagement grain: date × HCP × interaction type |
| `hcp_features.csv` | analytics | Pre-computed HCP RFM segmentation |
| `monthly_kpi_summary.csv` | analytics | Pre-aggregated KPIs with MoM/YoY growth |
| `market_share_drivers.csv` | analytics | Pre-computed share-movement explanations |
| `sales_forecast.csv` | analytics | Forecast + scenarios |
| `data_quality_report.csv` | analytics | DQ summary per table |

**Recommended approach:** import the `analytics_*` / feature CSVs directly
rather than re-deriving KPIs, growth rates, or segments in DAX/Tableau
calculated fields — that logic already lives in `src/feature_engineering.py`
and `src/forecasting.py` and should stay the single source of truth.

## 2. Relationships (star schema)

```
dim_product ──< fact_sales >── dim_hcp
     │                              │
     └──< fact_market               └──< fact_hcp_engagement
     └──< analytics_sales_forecast  └──< analytics_hcp_features (1:1 on hcp_id)
dim_date ──< (any fact table's date/month column)
```

- `product_id` is the join key between `dim_product` and every fact/analytics
  table that references a product.
- `hcp_id` is the join key between `dim_hcp` and every fact/analytics table
  that references an HCP.
- Build a `dim_date` table (Power BI: "New Table" with `CALENDAR()`, or use
  the `dim_date` table generated by `sql/02_load_data.sql`) and relate it to
  `txn_date` / `rx_date` / `month` columns for consistent time intelligence.

## 3. Pages / modules to build

### Page 1 — Commercial Performance
- **Cards:** Net Sales, Sales Growth %, Units, Prescription Volume, Market
  Share, Average Selling Price, Target Achievement % (if you add a targets
  table — not included in the synthetic data, add your own `targets.csv`
  keyed by product/month/region to enable this card).
- **Line chart:** Net sales by month (from `monthly_kpi_summary`).
- **Bar chart:** Net sales by product / by region.
- **Waterfall or 100% stacked bar:** Product contribution to total sales.
- **Combo chart:** MoM % and YoY % growth over time.

### Page 2 — Customer / HCP Analytics
- **Scatter plot:** `recency_days` (x) vs `monetary_value` (y), colored by
  `value_growth_segment`, sized by `frequency` — direct visual of the RFM
  segmentation from `hcp_features.csv`.
- **Bar chart:** HCP count by `value_growth_segment`.
- **Table:** Top 20 HCPs by `monetary_value`, with `hcp_segment` and
  `value_growth_segment` as slicers.
- **Table/Card:** "High Value / Low Engagement" HCPs that are also
  `hcp_segment = High potential` — the targeting list.

### Page 3 — Market & Competitive Analytics
- **Stacked bar / 100% bar:** Company vs competitor sales by product
  (latest month), from `market_data.csv`.
- **Line chart:** Market share trend by therapy area over time.
- **Table:** `market_share_drivers.csv` — `driver_explanation`,
  `company_sales_growth_pct`, `market_growth_pct`, `share_change_pp`.
- **Matrix:** Patient access approval/rejection rate by region × payer type.

### Page 4 — Forecasting & Scenario Analysis
- **Line chart:** Actual vs Base Case forecast, from `sales_forecast.csv`
  filtered to `scenario IN ('Actual','Base Case')`.
- **Line chart with 4 series:** Base Case / +5% / -5% / High-Demand
  scenarios for the forecast horizon.
- **Slicer:** Product (brand_name) to drill into product-level forecasts.

### Page 5 — Data Quality & Reporting
- **Table:** `data_quality_report.csv` as-is — one row per source table.
- **Cards:** Total records, % records removed, missing HCP mappings,
  duplicate records, negative-value records (filtered to the
  `sales_transactions` row).
- **Bar chart:** `pct_records_removed` by `table`.

## 4. Suggested DAX time-intelligence measures (Power BI)

```
Net Sales YTD = TOTALYTD(SUM(fact_sales[net_sales]), dim_date[date_key])

Net Sales MoM % =
VAR CurrentMonth = SUM(fact_sales[net_sales])
VAR PriorMonth = CALCULATE(SUM(fact_sales[net_sales]), DATEADD(dim_date[date_key], -1, MONTH))
RETURN DIVIDE(CurrentMonth - PriorMonth, PriorMonth)
```

(Prefer using the pre-computed `mom_growth_pct` / `yoy_growth_pct` columns
in `monthly_kpi_summary.csv` where possible, to avoid duplicating logic.)

## 5. Tableau notes

- Use `hcp_id` and `product_id` as the join keys the same way; Tableau's
  relationship model (not blending) handles the star schema well.
- Build the RFM scatter as a standard scatter plot with
  `value_growth_segment` on Color and `frequency` on Size.
- Use Tableau's built-in forecasting only for a quick sanity check —
  the shipped `sales_forecast.csv` (Holt-Winters via Python) is the
  source of truth for the scenario numbers shown on the dashboard.
